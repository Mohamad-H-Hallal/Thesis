# AI Integration Phase A to O Checkpoint

## Purpose

This checkpoint summarizes the AI integration work completed from Phase A through Phase O. It is a report-only checkpoint before choosing the next AI phase. It does not add app code, run GEE, train models, classify Lebanon, add Redis, merge branches, modify runtime database state, or commit generated outputs.

## What Is Implemented

### AI Schema and Provenance

- AI storage tables for settings, runs, logs, metrics, class statistics, output layers, uncertainty/review data, and review decisions.
- `spatial_feature.source` provenance so approved field data and AI outputs remain clearly separated.
- AI output storage in dedicated AI tables instead of mixing predictions into approved project features.
- Constraints, indexes, and audit fields for controlled AI workflows.

### AI Readiness, Settings, and Runs APIs

- Project AI readiness endpoint.
- AI settings endpoints.
- AI run create/list/detail endpoints.
- AI run logs, metrics, layers, and review endpoints.
- Protected super-admin access for AI controls.
- OpenAPI coverage for AI endpoints.

### Super-Admin AI Workspace

- Project AI workspace visible to protected super-admin only.
- Readiness, Settings, Runs, Results, Layers, and Review workflows.
- Clean classifier field selection using the admin/project-facing schema field, such as `L4_descr`.
- No real-execution claim when a run is mock, dry-run, or review-only.

### Worker Skeleton and Pipeline Bridge

- Safe AI worker skeleton with queued-run claiming, controlled status transitions, and `ai_run_log` entries.
- Concurrency guard so a run is not processed twice.
- Safe bridge to the AI repo through allowlisted commands and argument arrays.
- Pipeline config check, dry-run, readiness/probe, local ground truth export, regional feature extraction, regional model evaluation, and regional artifact preparation modes.
- No Redis dependency yet.

### Regional Worker Execution

- Controlled regional execution for the South Lebanon Fruit Trees Training Dataset.
- Local ground truth export.
- Sentinel-2 regional feature extraction.
- Regional model evaluation.
- Regional classification/vector review artifact preparation.
- Statuses and logs flow through app AI tables.
- No national classification and no viewer publication.

### Readable AI Run Result UI

- Human-readable run summary.
- Friendly execution mode and status labels.
- Compact model result summary.
- Output layer summary.
- Review result summary.
- Technical output files, logs, raw metadata, and detailed statistics hidden by default behind expandable sections.

### Artifact Registration

- Real regional artifacts registered into app AI tables.
- Structured model metrics stored in `ai_run_metric`.
- Class counts/statistics stored in `ai_class_statistic`.
- Classification, confidence, uncertainty, and statistics layer records stored in `ai_output_layer`.
- Registered layers remain unpublished and review-only.

### Review Workflow

- Protected super-admin review actions:
  - approve for future publication
  - reject
  - request more data
  - keep draft
- Review decisions stored in `ai_review_decision`.
- Review logs written to `ai_run_log`.
- Review wording makes clear that approval prepares a future publishing phase and does not publish to viewers now.

### AI Output Layer Visibility

- Project AI displays registered AI output layers.
- Layer statuses are shown with user-friendly labels such as Ready for review, Approved for future publication, Draft, Rejected, and Not published.
- Review decisions and comments are visible with layer/run context.
- Viewer-facing AI layer publishing remains disabled.

### Real Regional Review Artifacts

- Real regional review artifacts were generated by the AI repo for the South Lebanon proof-of-concept.
- Artifacts include classification, confidence, uncertainty, statistics, metadata, and vector review files where available.
- The app can register these artifacts as unpublished AI output layers.
- The map classifier is recorded honestly and is not claimed to be the same as the metric-selected model when it differs.

### Super-Admin AI Preview Map

- Dedicated AI preview map for protected super-admin review only.
- Classification, confidence, and uncertainty layer toggles.
- Layer legend and review-only warnings.
- AI feature details with prediction metadata and "not official field data" warning.
- Paginated AI feature list with search/filter over AI layer data.
- Project Map / Import Map style map controls and fit behavior.
- Optimized loading strategy to avoid Android freezes:
  - total layer counts are separate from visible/returned counts
  - inactive layers are not rendered
  - confidence and uncertainty lazy-load
  - requests are debounced and cached
  - overview/detail behavior preserves real geometry at detailed zoom
  - full feature geometry is fetched only when needed for selection/details

## Current Limitations

The following limitations remain intentional:

- No national classification.
- No public AI layer publishing.
- No final production worker queue.
- No Redis.
- No production scheduler.
- No automatic retraining.
- No viewer-facing Project Map AI layer toggle.
- No insertion of AI predictions into `spatial_feature`.

- Fruit Trees is a broad class.
- Vineyards are excluded because only 12 samples were available, below the usable training threshold.
- National data is still needed before any national accuracy or production national classification claim.

## Safety Guarantees

The current branch preserves these safety boundaries:

- Protected super-admin-only AI controls and preview.
- AI outputs are stored separately from `spatial_feature`.
- AI predictions are not inserted into official approved field data.
- AI output layers are review-only and unpublished.
- Viewer-facing AI layer publishing is disabled.
- Review approval means approved for a later publishing phase, not published now.
- No secrets are committed.
- `.env` values are not committed.
- GEE keys are not committed.
- Raw data is not committed.
- Generated AI outputs are not committed.
- Worker and pipeline commands remain controlled and allowlisted.
- Optimized map loading avoids rendering all heavy AI geometries at once and prevents the Android freeze encountered during Phase O.

## Recommended Next Options

### Option A: Pause and Stabilize for Demo/Thesis

Pause feature growth and stabilize the current A-O integration for demo, thesis writing, and handover. This should include one final end-to-end smoke pass, screenshots or video capture for documentation, and a concise operator guide.

### Option B: Phase P - Publishing Workflow to Viewers

Add a controlled publication workflow that exposes approved AI output layers to viewer-facing project maps only after explicit super-admin approval. This should include public visibility rules, audit logs, rollback/unpublish support, and clear viewer wording that the layer is AI-derived.

### Option C: Phase P Alternative - Contributor Uncertainty Validation Workflow

Use uncertainty areas as field validation tasks for contributors. This would let the app turn uncertain AI predictions into human review tasks without publishing final AI layers yet.

### Option D: Production Hardening and Deployment

Harden deployment, environment management, worker operations, observability, backup/restore, and production security before wider use.

## Recommended Next Step

Recommended next step: **Option A - pause and stabilize for demo/thesis**.

Reason: Phases A through O now prove the full integration path from approved field data to real regional AI review artifacts and super-admin map preview, while preserving the key safety boundary that AI outputs are not public and are not inserted into `spatial_feature`. Before adding viewer publishing or contributor validation, the safer move is to stabilize the current demo-ready proof, document it, and avoid new release risk.

After that checkpoint, the best technical continuation is likely Option C if the priority is data quality and field validation, or Option B if the priority is viewer-facing AI map delivery.
